Implementation Notes

Issue #30 — ROUTE-REFRESH Message Codec (RFC 2918) — 2026-06-26

Design Decisions

Decision Added dedicated RouteRefresh variant to BgpMessage enum

Ambiguity: The existing BgpMessage::Raw variant already handles unknown type codes (including type 5). Type 5 could have been left as Raw without a dedicated type.

Choice: Added BgpMessage::RouteRefresh(RouteRefreshMessage) as a first-class variant with proper dispatch in encode/decode.

Rationale: A dedicated variant enables type-safe construction, structural equality, and targeted fuzzing of the RouteRefresh body fields. Raw is reserved for truly unknown type codes. This follows the precedent set by all other known message types (Open, Update, Keepalive, Notification).

Decision No builder pattern for RouteRefreshMessage

Ambiguity: OpenMessage has a builder; whether new message types should follow that pattern was not specified.

Choice: Used a plain struct literal with public fields — no builder.

Rationale: RouteRefreshMessage has only 3 simple fields with no optional/compound sub-structures. A builder adds ~40 lines of boilerplate for zero ergonomic benefit at this scale. If the message grows optional parameters later, a builder can be added then.

Deviations

None — implementation follows the spec as written. The wire format <afi(2), reserved(1), safi(1)> matches RFC 2918 §2 exactly, and the zero-validation decode behavior matches the project's fuzzing-first codec philosophy.

Tradeoffs

Tradeoff Struct fields vs. [u8; 4] byte array

Alternatives: (A) Named struct fields {afi, reserved, safi} — chosen; (B) Raw [u8; 4] body with accessor methods.

Why A: Named fields make test assertions self-documenting (assert_eq!(decoded.afi, 1) vs. assert_eq!(decoded.body[0], 0)), prevent byte-ordering bugs at construction sites, and match the pattern of every other message type in the crate. Option B would be more compact but opaque — the 4-byte body doesn't justify the readability loss.

Open Questions

None — the acceptance criteria were specific and testable. All criteria verified: tests pass, clippy clean, wire format byte-verified against RFC 2918.
