Implementation Notes

Issue #31 — BGP Capability Structured Codec (RFC 5492) — 2026-06-26

Design Decisions

Decision MultiProtocol capability stores afi/safi but not reserved byte

Ambiguity: The MP capability value is AFI(2) + Reserved(1) + SAFI(1), but the spec only mentions {afi, safi} as fields.

Choice: Expose only afi and safi as named fields. The reserved byte is written as 0 on encode and silently skipped on decode.

Rationale: The reserved byte is always 0 per RFC 4760 and carries no semantic information. Keeping it out of the public API avoids noise while the wire format remains correct.

Decision GracefulRestart families stored as raw Vec<u8>

Ambiguity: Each family entry is AFI(2)+SAFI(1)+Flags(1)=4 bytes, but the spec didn't specify whether to parse them into structs.

Choice: Store as opaque Vec<u8> — raw bytes.

Rationale: Consistent with the project's zero-validation fuzzing philosophy. Structured parsing would require validation that the fuzzer needs to bypass. Callers who need structured families can parse the bytes themselves.

Decision encode truncates value bytes to declared_len

Ambiguity: When declared_len is smaller than the structured value, should encode write fewer bytes or all bytes?

Choice: Truncate to declared_len. Decode consumes exactly 2 + declared_len bytes for position tracking.

Rationale: Encode and decode must agree on byte boundaries for capability sequence round-trips through CapabilitiesOptParam. Without truncation, a capability with mismatched declared_len would corrupt the offset for the next capability in the sequence.

Deviations

None — implementation follows the spec as written. All five capability types are supported, declared_len is preserved, and the wire format matches RFC 5492.

Tradeoffs

Tradeoff Field defaults vs. Incomplete error on short value

Alternatives: (A) Default to 0/empty when value bytes are too short — chosen; (B) Return DecodeError::Incomplete.

Why A: The fuzzing codec must never reject input. Defaulting to 0 preserves the declared_len and type_code while avoiding panics. The caller can detect the truncation by comparing declared_len against the expected value size for that type.

Open Questions

None — all acceptance criteria met with passing tests and clean clippy.
